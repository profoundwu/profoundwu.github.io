用 Claude Code 开发时，反复解释需求、搜索无关文件、带着旧讨论继续工作，都会增加时间和调用成本。下面这四个工作习惯，可以帮助我们减少返工和不必要的上下文开销，让任务完成得更好、更快、更省。

## 一、复杂需求先用强模型，把方案讨论清楚
遇到复杂需求，可以优先用理解和推理能力更强的模型讨论方案。先确认目标、约束、边界情况和验收标准，再开始实现，有助于减少因理解偏差造成的返工。

## 二、缩小任务范围，提供必要上下文

### 大任务先拆成能独立验收的小任务

拆任务时，为每个任务写清目标、所需资料和交付结果，让 Agent 能判断自己需要做什么、做到什么程度。

适合独立探索的部分，可以交给子 Agent，在它自己的上下文中完成搜索，再把结论带回主会话。依赖紧密、需要反复共享背景的步骤，则可以留在同一会话中处理。[子 Agent 使用说明](https://claude.com/blog/subagents-in-claude-code)

每个任务只带上完成它需要的背景，并为后续搜索、工具输出和修改留出空间。拆分是否合适，主要看任务能否独立完成和验收，不必机械地追求固定的上下文占比。

### 知道资料在哪，就直接给位置

熟悉代码或文档的位置时，可以用 `@` 指定文件，再说明要处理的函数、章节或段落。

例如：

> 请检查 @login.ts 中的 `handleLogin` 函数，补上邮箱为空时的校验。

这比只说“帮我修一下登录”更容易让 Agent 找到相关内容。

确实需要搜索时，也尽量限定目录、关键词和问题范围。

### 讨论有了结论，就整理成文档交接

一轮讨论结束后，把已经确定的内容整理成简短文档。接手的 Agent 就能从结论开始，不必重新梳理整段讨论。

例如，确定登录功能的改造方案后，可以让当前 Agent 整理交接文档：

> 请将已确认的目标、约束、方案、相关文件、验收标准和待办事项整理到 `handoff.md`，并单独标出尚未确定的问题。

然后开启新会话：

> 请阅读 handoff.md，按照其中的方案和待办事项，完成登录功能的修改。

交接文档应分清“已经决定的内容”和“仍需确认的问题”，避免接手的 Agent 把讨论中的猜测当成定论。也可以使用 [Matt Pocock 的 handoff skill](https://github.com/mattpocock/skills/blob/main/skills/productivity/handoff/SKILL.md) 帮助整理。

## 三、别让无关上下文跟着任务走

对话记录、读取过的文件和工具信息都会占用上下文。任务已经改变，旧讨论却还留在当前会话里，既增加输入开销，也可能影响后续判断。

### 换了任务，就开一个干净会话

准备处理一项无关的新任务时，可以先输入 `/clear`，再提交新的需求。Claude Code 会清空当前对话上下文，并保存之前的会话，需要时可以通过 `/resume` 找回。

如果仍在处理同一任务，只是讨论太长，可以用 `/compact` 将历史压缩成摘要。拿不准哪些内容占用了空间时，可以先运行 `/context` 查看。[会话管理说明](https://code.claude.com/docs/en/sessions#manage-context-within-a-session)

### 要求写错了，就回到出错前修改

如果 Claude Code 回答后，你才发现原来的要求写错了，可以输入 `/rewind`，或在输入框为空时连续按两次 `Esc`，打开回退菜单。

选中原来的消息后，可以仅恢复对话，也可以同时恢复代码和对话。恢复对话后，原要求会回到输入框，便于修改后重新提交。只恢复对话会保留当前代码，因此要根据已经发生的修改选择恢复方式。[回退操作说明](https://code.claude.com/docs/en/checkpointing#rewind-and-summarize)

### 按需启用 Skill、插件和 MCP 服务

**低频 Skill 改为手动调用。** 默认情况下，Claude Code 会将 Skill 的名称和说明放入上下文，调用时再加载完整内容。对于偶尔才用的普通 Skill，可以在 `/skills` 中选中它，按空格切换到 `user-only`，再按 `Esc` 保存。这个状态对应的配置值是 `user-invocable-only`：Claude 不会自动调用，你仍然可以通过 `/skill-name` 手动使用。

插件提供的 Skill 不受这项设置控制，需要通过 `/plugin` 管理。[Skill 管理说明](https://code.claude.com/docs/en/skills#override-skill-visibility-from-settings)

**暂时停用用不到的插件。** 输入 `/plugin`，进入 `Installed` 页面，选中插件并选择 `Disable`。当前版本退出菜单时会自动尝试应用变更；如果界面提示变更仍待生效，再按提示处理。通过菜单以外的方式修改插件后，可以运行 `/reload-plugins` 重新加载。[插件管理说明](https://code.claude.com/docs/en/discover-plugins#apply-plugin-changes-without-restarting)

**MCP 服务按任务启用。** 输入 `/mcp` 查看连接，暂时用不到的服务可以直接停用，保留配置供以后使用。插件提供的 MCP 服务也可以在这里单独停用，无需关闭整个插件。

启用工具搜索时，MCP 工具的完整定义会按需加载，但工具名称和服务说明仍会占用部分上下文。因此，可以定期整理连接，也不必在每轮对话前反复开关。[MCP 管理说明](https://code.claude.com/docs/en/mcp#disable-a-server-without-removing-it)

## 四、复用缓存，减少重复处理

Claude Code 会自动管理提示词缓存。后续请求复用已经处理过的输入时，可以降低输入成本并缩短等待时间。

缓存不会把旧讨论从上下文中移除。同一任务需要的背景可以继续复用；不再相关的内容，仍然应该及时清理。

### 同一项任务尽量连续处理

缓存能保留多久，取决于请求使用的缓存期限。默认情况下：

| 计费方式                     | 主会话的缓存期限 |
| ------------------------ | -------- |
| 使用 Claude 订阅套餐内的额度       | 1 小时     |
| 使用 API Key、云服务商或套餐外的付费额度 | 5 分钟     |

每次请求命中缓存，都会重新计时。例如，使用 1 小时缓存时，10:00 命中，期限延长到 11:00；10:40 再次命中，就延长到 11:40。

因此，同一项任务尽量连续处理，有利于复用缓存，无需在一小时内完成整个任务。自定义配置可能改变期限，子 Agent 等辅助请求也可能使用不同期限。[缓存期限说明](https://code.claude.com/docs/en/prompt-caching#cache-lifetime)

### 模型和工具尽量在开始前确定

缓存复用依赖请求前面的内容保持一致。如果前面的内容改变，从变化位置开始的后续内容就可能需要重新处理。

开始任务前，可以先确定模型、思考强度和所需工具，减少工作中途不必要的调整。常见操作的影响如下：

| 操作                    | 对缓存的影响                              |
| --------------------- | ----------------------------------- |
| 切换模型                  | 不同模型使用各自的缓存，切换后的首次请求无法复用原模型的缓存。     |
| 调整思考强度                | 在大多数模型上会使缓存失效，部分模型和接入方式支持保留缓存。      |
| 首次开启快速模式              | 会使当前会话的缓存失效，并按快速模式价格重新处理输入。         |
| 改变预先加载的工具定义           | 可能影响缓存；按需加载的 MCP 工具发生变化时，通常不影响已有缓存。 |
| 累积过多图片或 PDF           | 触及限制后，移除旧内容会影响从该位置开始的缓存复用。          |
| 升级 Claude Code 后启动新会话 | 系统提示词或工具定义可能变化，需要重新建立缓存。            |

具体条件见[缓存失效说明](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache)。

这些影响可以帮助安排工作，但不必为了保住缓存而拖延必要的调整。模型不合适、需求理解错了，或任务已经切换时，及时纠正通常更有价值。
